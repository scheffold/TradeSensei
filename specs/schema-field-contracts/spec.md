# Schema Field Contracts Specification

## Overview

This specification defines the exhaustive field lists, type constraints, defaults, and validation boundaries for execution and trade merge schemas.

---

## LogicalExecutionCreate Schema

### Purpose
Request body for creating a manual logical execution via `POST /api/v1/trades/{trade_id}/executions`.

### Required Fields

| Field       | Type     | Constraints                    | Description                                |
|-------------|----------|--------------------------------|--------------------------------------------|
| direction   | Direction| LONG or SHORT                  | Buy or sell side of the execution          |
| quantity    | Decimal  | > 0 (gt=0)                     | Execution quantity (absolute, always positive) |
| price       | Decimal  | >= 0 (ge=0)                    | Execution price per unit                   |
| executed_at | datetime | timezone-aware (UTC)           | Timestamp of the execution                 |

### Optional Fields

| Field      | Type     | Default | Constraints | Description                                |
|------------|----------|---------|-------------|-------------------------------------------|
| commission | Decimal  | 0.0     | >= 0        | Commission for this execution leg          |
| pnl        | Decimal  | None    | None        | Broker-reported realised P&L (None for opening legs) |

### Validation Rules

1. **direction**: Must be one of `Direction.LONG` or `Direction.SHORT`
2. **quantity**: Must be strictly positive (> 0)
3. **price**: Must be non-negative (>= 0)
4. **commission**: Defaults to `Decimal("0.0")` if omitted; must be >= 0
5. **executed_at**: Must be timezone-aware; naive datetimes are rejected
6. **pnl**: Optional; can be `None` for opening legs

### Example Valid Payloads

```json
{
  "direction": "LONG",
  "quantity": "100",
  "price": "150.50",
  "executed_at": "2025-01-15T10:00:00Z"
}
```

```json
{
  "direction": "SHORT",
  "quantity": "50",
  "price": "160.00",
  "commission": "2.50",
  "executed_at": "2025-01-15T11:00:00Z",
  "pnl": "500.00"
}
```

## LogicalExecutionRead Schema

### Purpose
Response body for reading a logical execution (GET endpoints).

### All Fields (19 total)

| Field       | Type                | Nullable | Description                                |
|-------------|---------------------|----------|-------------------------------------------|
| id          | UUID                | No       | UUID primary key generated by the database |
| user_id     | UUID                | No       | Foreign key to the owning User             |
| account_id  | UUID                | Yes      | Optional foreign key to Account            |
| symbol      | str                 | No       | Ticker symbol                              |
| conid       | str                 | Yes      | Broker contract identifier                 |
| asset_class | AssetClass          | No       | Asset class (EQUITY, OPTION, FUTURE, etc.) |
| direction   | Direction           | No       | LONG or SHORT                              |
| quantity    | Decimal             | No       | Execution quantity (absolute, always positive) |
| price       | Decimal             | No       | Execution price per unit                   |
| commission  | Decimal             | No       | Commission for this execution leg          |
| executed_at | datetime            | No       | Timestamp of the execution (UTC)           |
| pnl         | Decimal             | Yes      | Broker-reported realised P&L               |
| pnl_eur     | Decimal             | Yes      | Realised P&L converted to EUR              |
| multiplier  | int                 | No       | Contract multiplier (1 for equities, >1 for futures/options) |
| currency    | str                 | Yes      | ISO-4217 currency code (e.g. "USD")        |
| status      | ExecutionStatus     | No       | One of: imported, manual, merged, split    |
| trade_id    | UUID                | Yes      | Optional foreign key to Trade              |
| created_at  | datetime            | No       | Row-creation timestamp (UTC)               |
| updated_at  | datetime            | No       | Row-update timestamp (UTC)                 |

### Field Type Constraints

- **id, user_id, account_id, trade_id**: UUID v4
- **symbol**: str, max_length=30
- **conid**: str, max_length=50
- **asset_class**: Enum (EQUITY, OPTION, FUTURE, FOREX, CRYPTO)
- **direction**: Enum (LONG, SHORT)
- **quantity**: Decimal, > 0
- **price**: Decimal, >= 0
- **commission**: Decimal, >= 0
- **executed_at, created_at, updated_at**: datetime with timezone (UTC)
- **pnl, pnl_eur**: Decimal or None
- **multiplier**: int, >= 1
- **currency**: str (ISO-4217 code) or None
- **status**: Enum (imported, manual, merged, split)

### Serialization

- Constructed from ORM instance via `from_attributes=True`
- All fields are read-only (no write operations via this schema)

## LogicalExecutionUpdate Schema

### Purpose
Request body for updating a logical execution via `PATCH /api/v1/executions/{execution_id}`.

### All Fields (Optional)

| Field       | Type     | Default | Constraints | Description                                |
|-------------|----------|---------|-------------|-------------------------------------------|
| direction   | Direction| None    | LONG or SHORT | Buy or sell side of the execution          |
| quantity    | Decimal  | None    | > 0         | Execution quantity (absolute, always positive) |
| price       | Decimal  | None    | >= 0        | Execution price per unit                   |
| commission  | Decimal  | None    | >= 0        | Commission for this execution leg          |
| executed_at | datetime | None    | timezone-aware | Timestamp of the execution                 |
| pnl         | Decimal  | None    | None        | Broker-reported realised P&L               |

### Validation Rules

1. **All fields are optional**: An empty payload `{}` is valid
2. **Partial updates**: Only explicitly-set fields are included in `model_dump(exclude_unset=True)`
3. **quantity**: If provided, must be > 0
4. **price**: If provided, must be >= 0
5. **commission**: If provided, must be >= 0
6. **executed_at**: If provided, must be timezone-aware

### Example Valid Payloads

```json
{}
```

```json
{
  "price": "160.00"
}
```

```json
{
  "quantity": "50",
  "commission": "2.50"
}
```

## MergeTradesRequest Schema

### Purpose
Request body for merging multiple trades via `POST /api/v1/trades/merge`.

### Required Fields

| Field     | Type           | Constraints                    | Description                                |
|-----------|----------------|--------------------------------|--------------------------------------------|
| trade_ids | list[UUID]     | min_length=2, max_length=10    | List of trade UUIDs to merge               |

### Validation Rules

1. **trade_ids**: Must contain at least 2 UUIDs
2. **trade_ids**: Must contain at most 10 UUIDs
3. **trade_ids**: Empty list is rejected
4. **trade_ids**: All UUIDs must be valid UUID v4 format

## Test Implementation Requirements

### LogicalExecutionCreate Tests
- Valid payload with all fields
- Valid payload with only required fields (commission defaults to 0)
- Reject zero quantity
- Reject negative price
- Reject naive datetime
- Reject negative commission

### LogicalExecutionRead Tests
- Construct from ORM instance with all fields populated
- Construct from ORM instance with optional fields as None
- Verify all 19 fields are present and have correct types

### LogicalExecutionUpdate Tests
- Empty payload is valid
- Partial update with single field
- Partial update with multiple fields
- Reject zero quantity when provided
- Reject negative price when provided
- Reject negative commission when provided
- Reject naive datetime when provided

### MergeTradesRequest Tests
- Valid payload with 2 trades
- Valid payload with 10 trades (maximum)
- Reject payload with 1 trade
- Reject payload with 11 trades
- Reject empty list
