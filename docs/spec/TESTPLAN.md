# Playwright Test Plan (English)

This document describes how to run the Playwright E2E test suite for the Trade Sensei frontend, the recommended environment, and useful commands for running subsets of tests.

Prerequisites
- Node.js (v18+) and npm installed
- Playwright installed as a dev dependency (project already contains Playwright config)
- Backend API running locally (default: http://localhost:8000)
- Frontend dev server running locally (default: http://localhost:3000)
- Optional: Docker Compose setup for the full stack (see repo root compose files)

Environment variables
- E2E_BASE_URL — frontend base URL (default: http://localhost:3000)
- E2E_API_URL — backend API URL (default: http://localhost:8000)

Local dev start (example using npm)
1. Start backend and DB (example using Docker Compose):
   - docker compose up -d
2. Start frontend in dev mode (if not already running):
   - npm run dev --workspace frontend

Playwright commands
- Run the whole suite (headless):
  - npx playwright test
- Run the whole suite in headed mode (see browser UI):
  - npx playwright test --headed
- Run a single spec file:
  - npx playwright test frontend/tests/specs/trades.spec.ts
- Run tests matching a grep (TC id or keyword):
  - npx playwright test --grep "Trades|TC-05"
- Run only tests tagged or with a describe name (use test.describe.skip in code to temporarily skip)

Useful options
- Show the Playwright HTML report after a run (report generated by default in playwright-report/):
  - npx playwright show-report
- Run with a single worker to avoid state races:
  - npx playwright test --workers=1
- Increase timeout for slow CI or slow local environments:
  - npx playwright test --timeout=60000

Test data and seed flow
- The repository contains a `frontend/tests/global-setup` that seeds an E2E user and test data. Ensure that global setup runs (Playwright config uses it by default).
- Some tests read `.auth/seed-state.json` or `frontend/tests/fixtures/*`. If you run tests in a fresh environment, run the global setup or recreate seed artifacts before executing dependent specs.

Debugging tips
- Use `--debug` to run Playwright in interactive mode (breaks on first failure):
  - npx playwright test --debug
- Capture trace and video for a failed test (configure in playwright.config or via CLI):
  - npx playwright test --trace on --output-trace

CI recommendations
- Run linter and type checks before running E2E tests to fail fast.
- Run Playwright with `--workers=2` in CI depending on available resources; use `--workers=1` if tests are flaky due to shared state.
- Upload `playwright-report` (HTML) as build artifact for failed runs.

Run matrix examples
- Quick smoke (navigation + auth only):
  - npx playwright test frontend/tests/specs/auth.spec.ts frontend/tests/specs/navigation.spec.ts --workers=1
- Full suite (headless, 2 workers):
  - npx playwright test --workers=2

Addendum: Common commands for this repo (zsh)
- Install dependencies (root):
  - npm install
- Install Playwright browsers (if needed):
  - npx playwright install
